# Milestone Technical Report 3: Calling Agent System Prompt Implementation

## 1. Executive Summary

This milestone successfully implements the complete Calling Agent System Prompt in the AI Calling Agent backend. The system establishes `backend/system_prompt.py` as the centralized authority for prompt formatting, dynamic user personalization (`{{user_first_name}}`, `{{user_last_name}}`, `{{assistant_name}}`), and contextual call injection (`user_preferences`, contact classification, `historical_memory`, `learned_memory`).

The calling agent system prompt is consistently passed as the `system` message to the local Qwen/Ollama engine across every multi-turn turn, strictly adhering to caller-receptionist behavior rules, confidentiality mandates, and decision engine routing.

## 3. How System Prompt Loading Works

1. **Centralized Template Maintenance**:
   - Primary prompt text is maintained in `backend/system_prompt.txt` and mirrored in `backend/system_prompt.py` (`DEFAULT_SYSTEM_PROMPT_TEMPLATE`).
   - When `load_raw_system_prompt_template()` is called, it inspects `backend/system_prompt.txt`. If present and non-empty, it reads the latest file contents immediately. If missing or unreadable, it falls back safely to the hardcoded module default.
2. **Dynamic Context Separation**:
   - The base 14 sections of the prompt remain static to preserve core behavioral boundaries (Identity, Personality, Opening, Understanding, Conversation Handling, Privacy, Hold/Takeover, Operating Principles).
   - Dynamic parameters and contextual memories are appended under a distinct section: `## 15. Dynamic Call Context & Internal Memories`.

---

## 4. User Identity Retrieval and Dynamic Personalisation

### Database Mapping:
- Authenticated `user_id` (UUID) is extracted from Supabase JWT validation.
- `fetch_user_profile` executes:
  ```python
  client.table("users").select("first_name, last_name, assistant_name").eq("user_id", user_id).limit(1).execute()
  ```
- No schema alterations or new columns/tables were created.

### Dynamic Placeholders:
- `{{user_first_name}}` -> User's first name (e.g. `rudra`)
- `{{user_last_name}}` -> User's last name (e.g. `gandhi`)
- `{{assistant_name}}` -> User's chosen assistant name (e.g. `Siri`)

### Graceful Fallbacks & Logging:
- If `first_name` is missing or empty: logs a warning and substitutes `"the user"`.
- If `last_name` is missing: logs a warning and omits the last name placeholder cleanly without double-spacing.
- If `assistant_name` is missing: logs a warning and substitutes `"Assistant"`.
- Never invents false identities or hardcodes user names.
- Strict multi-user isolation: User A's session exclusively uses User A's identity; User B's session exclusively uses User B's identity.

---

## 5. Dynamic Context & Confidentiality Protection

Dynamic context is retrieved on-demand per call session via `fetch_dynamic_context(user_id, caller_phone_number)`:
1. **User Preferences**: Retrieves active preferences from `user_preferences` (e.g., call handling rules).
2. **Caller Context**: Checks `priority_contacts` and `contacts` by `phone_number` and `user_id`. Identifies whether the caller is a PRIORITY CONTACT or a KNOWN CONTACT.
3. **Historical Memory**: Queries active records from `historical_memory` (ordered by `created_at desc`, limited to 3).
4. **Learned Memory**: Queries active records from `learned_memory` (ordered by `confidence desc`, limited to 3).

### Strict Confidentiality Guard:
All dynamic context injected into Section 15 is prefixed with an unambiguous prompt directive:
> `CONFIDENTIALITY MANDATE: The following contextual details are provided strictly for your internal reference to assist the call. You MUST NEVER disclose, quote, or reveal these internal user preferences, memories, or notes to the caller unless explicitly authorized by the user.`

This ensures the agent uses historical context to understand the conversation without disclosing private user details, internal instructions, or notes.

---

## 6. Decision Engine Restrictions & Compliance

The Calling Agent System Prompt reinforces backend decision engine authority:
- **Rule Enforcement**: The existing call decision engine retains exclusive authority over `HANDLE`, `DECLINE`, and `ESCALATE`.
- **Transfer Restrictions**: The agent never independently initiates transfers or tells callers that a transfer has completed until confirmed by the backend.
- **Priority Routing**: Priority contact routing is strictly respected and never bypassed.
